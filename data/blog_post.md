# AI Governance 구축 전략과 핵심

오므니사(Omnissa)가 엘라라(Elara)라는 권한 계층을 내놓으며 기업 AI 거버넌스 시장에 새 기준을 제시했다. 도쿄 마린(Tokio Marine)이 모니터(Monitaur)를 도입해 거버넌스를 운영 체계로 녹여낸 사례도 동시에 나왔다. 현장에서 느끼기엔 이제 모델 배포가 끝이 아니라, 에이전트 자율 행동까지 통제할 수 있는 권한 계층이 필수 인프라가 되었다.

## 1. 현장에서 무슨 일이 있었나

오므니사가 엘라라를 발표했다. IT 운영용 AI 에이전트, 관리형 클라우드 PC 서비스와 함께 공개된 엘라라는 '권한 계층(Authority Layer)'이라는 개념으로 고위험 기업 행동을 제어한다. 기사에 따르면 엘라라는 정책 기반 의사결정, 실시간 집행, 감사 추적 기능을 단일 계층에서 제공한다. 별도 보도자료에서는 엘라라가 자율 에이전트 실행 전후로 정책 검증과 승인 워크플로를 강제한다고 명시했다. 한편 도쿄 마린 미국 법인은 모니터 플랫폼을 선택해 전사 AI 거버넌스를 운영화했다. 보험업 특성상 모델 리스크, 데이터 편향, 규제 대응을 문서화가 아닌 시스템 레벨에서 자동화하려는 시도로 읽힌다. 씨아이오닷컴(CIO.com) 기고에서는 거버넌스 업무가 감당하기 힘든 잡무로 변질되고 있다고 지적했다. 자율 에이전트 확산과 계약 지능(Contract Intelligence) 수요가 맞물리며 거버넌스 범위가 폭발적으로 늘었기 때문이다.

## 2. 왜 업계가 반응하는가

기존 거버넌스는 모델 학습과 배포 파이프라인에 집중됐다. 지금은 자율 에이전트가 외부 시스템을 호출하고, 계약을 체결하며, 인프라를 변경하는 단계까지 왔다. 오므니사 엘라라가 '고위험 기업 행동'을 제어 대상으로 삼은 이유가 여기에 있다. 에이전트 한 번 실수로 클라우드 리소스 삭제, 규정 위반 계약 체결, 민감 데이터 유출이 발생하면 롤백 비용이 감당 불가능하다. 도쿄 마린 사례처럼 금융권은 설명 가능성, 감사 추적, 규제 매핑을 수작업으로 커버할 수 없는 임계점을 넘었다. 씨아이오닷컴 지적대로 정책 문서만 늘어나고 실행 계층이 없으면 거버넌스는 조직 병목만 키운다. 업계가 권한 계층, 정책 엔진, 자동 증거 수집 같은 '실행 가능한 거버넌스 인프라'에 주목하는 배경이다.

## 3. 기술적으로 보면

- **권한 계층(Authority Layer)**: 에이전트 실행 요청을 가로채 정책 엔진에 질의하고, 승인·거부·조건부 실행을 강제하는 미들웨어 계층. 오므니사 엘라라가 이 역할을 수행한다.
- **정책 집행 포인트(Policy Enforcement Point)**: 코드 레벨이 아닌 인프라·API 게이트웨이·데이터 카탈로그 등 실행 경로 곳곳에 심어진 체크포인트. 실시간 차단과 로깅을 동시에 처리한다.
- **라이프사이클 거버넌스(Lifecycle Governance)**: 데이터 수집·라벨링, 모델 학습·검증, 배포·모니터링, 폐기까지 전 단계에 정책 태그를 붙여 추적하는 체계. 모니터 플랫폼이 이 흐름을 자동화한다.
- **자율 에이전트 거버넌스(Autonomous Agent Governance)**: 도구 호출(Tool Use), 메모리 접근, 외부 시스템 트랜잭션 등 에이전트 행위 단위별로 권한 스코프를 정의하고 위반 시 격리하는 메커니즘.
- **계약 지능(Contract Intelligence)**: 에이전트가 맺는 계약, 약관, SLA를 머신 리더블(Machine-readable) 형태로 파싱해 정책 위반 여부를 자동 판별하는 기능. 타임스 오브 인디아 기사에서 핵심 영역으로 지목됐다.

## 4. 실제 현장 적용 사례

오므니사 엘라라는 IT 운영 에이전트가 서버 재부팅, 권한 변경, 네트워크 정책 수정 같은 고위험 명령을 내릴 때 작동한다. 엘라라 계층은 요청 컨텍스트(요청자, 대상 리소스, 시간, 의도)를 정책 엔진에 전달하고, 사전 정의된 규칙·승인 워크플로·비상 차단 리스트를 평가해 실행 여부를 결정한다. 모든 판단 근거는 불변 로그로 저장돼 감사 대응에 바로 쓰인다. 도쿄 마린은 모니터를 통해 모델 리스크 카드(Model Risk Card) 자동 생성, 규제 매핑 라이브러리 연동, 데이터 드리프트 탐지 알림을 CI/CD 파이프라인에 심었다. 분기별 문서 검토 대신 배포 시점마다 거버넌스 증거가 자동 축적되는 구조다. 두 사례 공통점은 거버넌스를 '별도 프로세스'가 아닌 '실행 경로 위 필수 계층'으로 박아넣었다는 점이다.

## 5. 엔지니어가 봐야 할 포인트

회사에서 마이크로서비스 게이트웨이에 정책 엔진을 붙여본 경험으로는, 권한 계층 도입 시 지연 시간과 가용성이 첫 번째 병목이다. 엘라라처럼 사이드카(Sidecar)나 서비스 메시 레벨에서 정책 판단을 내려야 애플리케이션 코드 수정을 피할 수 있다. 실무에서 보면 정책 언어를 리고(Rego)나 세달(Cedar) 같은 선언형으로 통일하지 않으면, 팀마다 다른 규칙 엔진을 쓰다가 통합 감사가 불가능해진다. 또 에이전트 호출 체인이 길어지면 분산 추적(Distributed Tracing)과 정책 로그를 상관관계 분석할 수 있는 옵저버빌리티 스택이 선행돼야 한다. 데이터 카탈로그와 모델 레지스트리에 거버넌스 메타데이터(분류, 소유자, 승인 이력)를 필수 태그로 강제하는 CI 게이트도 빼놓을 수 없다. 결국 거버넌스는 문서가 아니라, 배포 파이프라인과 런타임 인프라에 심는 '자동화된 가드레일'이다.

## 6. 앞으로 볼 포인트

- 권한 계층 표준화 경쟁이 오므니사, 모니터, 클라우드 벤더 사이에서 본격화될 것이다
- 에이전트 간 통신 프로토콜(MCP, A2A 등)에 거버넌스 메타데이터가 표준 필드로 포함될 것이다
- 규제 당국이 '알고리즘 영향 평가' 제출 시 자동 생성 증거 패키지를 요구하는 방향으로 가이드라인을 구체화할 것이다

## 7. 3줄 요약

- 오므니사 엘라라와 도쿄 마린 모니터 도입 사례는 거버넌스를 실행 계층에 심는 권한 계층 아키텍처가 실전 검증됐음을 보여준다
- 자율 에이전트 확산으로 정책 집행, 계약 지능, 라이프사이클 추적이 인프라 레벨에서 자동화되지 않으면 운영 불가능한 수준에 도달했다
- 엔지니어는 게이트웨이·사이드카·CI 게이트에 선언형 정책 엔진을 박고, 분산 추적과 메타데이터 태깅을 선행 투자해야 한다
