# Agentic AI, 자율 실행의 핵심

마이크로소프트가 자사 모델과 에이전트형 AI 연속 개선 기능 업데이트를 함께 내놨다는 소식이 실무자 채팅방에 먼저 돌았다. 나는 그 공지보다 EY와 Stuut이 기업 자금 흐름 문제에 같은 기술을 걸었다는 소식이 더 실감 났다.

## 1. 현장에서 무슨 일이 있었나

실리콘앵글 보도는 마이크로소프트가 자체 모델을 새로 내고 에이전트형 AI 연속 개선 기능을 업데이트했다고 전했다. 핵심은 모델 성능 숫자가 아니다. 에이전트가 작업을 반복하면서 스스로 품질을 끌어올리는 루프가 제품에 들어갔다는 점이다. 더 퍼블럼 그룹은 EY와 Stuut이 기업 캐시플로우 개선에 에이전트형 AI를 걸었다고 보도했다. 클라우드 워즈는 마이크로소프트의 조지 글란츠슈니거가 ERP가 이 기술 때문에 값어치를 다시 얻는다고 발언한 자리를 옮겼다.

## 2. 왜 업계가 반응하는가

반응은 보안 쪽에서 먼저 나왔다. AI News는 기업 팀용 에이전트형 AI 보안 툴을 7개로 묶어 소개했다 [출처: 7 best agentic AI security tools for enterprise teams]. iTWire는 에이전트 하니스 보안을 위한 통제 항목을 5가지로 정리했다 [출처: Securing agentic AI harnesses: five controls to reduce enterprise risk]. Futuriom은 에이전트형 AI 시대에 맞춰 보안 네트워크형 서비스(NaaS)를 어떻게 지어야 하는지 다뤘다. TechTarget은 파티 풍선 구매 경험을 빗대 에이전트형 AI 구매 실패담을 썼다. 벤더 설명보다 구매 기준과 실패 조건을 먼저 정하라는 교훈이 담겼다.

## 3. 기술적으로 보면

- **목표 설정(goal setting)**: 사람이 최종 상태를 정의한다. 목표가 흐릿하면 실행이 표류한다.
- **계획(planning)**: 목표를 단계로 분해한다. 각 단계에 검증 조건을 붙여야 중간에 멈출 수 있다.
- **도구 호출(tool call)**: 에이전트가 API나 데이터베이스를 직접 두드린다. 권한 범위가 곧 사고 크기다.
- **자기 수정(self-correction)**: 실행 결과를 다시 읽고 계획을 고친다. 연속 개선 루프가 돌아가는 지점이다.
- **에이전트 하니스(harness)**: 모델 밖에 얹은 제어 틀이다. 입력 필터, 권한, 로그, 중단 조건이 여기 모인다.

## 4. 실제 현장 적용 사례

적용 사례는 세 갈래다. ERP 쪽은 주문부터 정산까지 이어지는 흐름에서 에이전트가 다음 단계 작업을 대신 처리한다. 자금 쪽은 수금 지연, 미결제 잔액 같은 자료를 계속 읽고 조치를 제안한다. 보안 쪽은 에이전트 자체가 감시 대상이 됐다. 툴 리스트와 하니스 통제 목록이 같은 시기에 나온 이유다. 공통점은 사람이 최종 판단은 남기고 반복 작업만 넘겼다는 점이다.

## 5. 엔지니어가 봐야 할 포인트

회사에서 이런 구조를 붙여본 경험을 기준으로 하면, 실패는 대부분 목표 단계에서 시작된다. "응답을 좋게 만들어라" 같은 목표는 측정이 안 되고 에이전트는 그걸 끝까지 믿고 따른다. 실무에서 보면 권한을 먼저 자르는 게 답이다. 도구 목록은 읽기 전용으로 줄이고 쓰기 권한은 단계별로 따로 준다. 내가 보기엔 자기 수정 기능을 켜두면서 로그를 안 남기는 팀이 가장 위험하다. 수정 과정이 기록에 없으면 사고 원인을 처음부터 다시 찾아야 한다.

## 6. 앞으로 볼 포인트

- 모델 제공업체가 연속 개선 기능을 표준으로 밀어붙이면, 도입 측은 개선 이력을 어떻게 검증할지 정해야 한다.
- 보안 툴과 하니스 통제 목록이 경쟁할 때, 규제 감사에서 통과하는 쪽이 시장을 가져간다.
- ERP와 자금 관리처럼 데이터가 닫힌 영역에서 성과 숫자가 먼저 나오고, 그다음 다른 산업으로 퍼질 것이다.

## 7. 3줄 요약

- 에이전트형 AI는 목표 설정, 계획, 도구 호출, 자기 수정을 한 바퀴 도는 구조다.
- 사고 크기는 도구 권한에서 결정되므로 하니스 통제가 먼저다.
- 연속 개선 루프가 제품에 들어간 지금, 개선 이력 검증 능력이 도입 성패를 가른다.
