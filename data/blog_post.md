# 디지털 트윈 레벨업: L1-L4 구축과 OpenUSD

지난주 AWS가 L1부터 L4까지 산업용 디지털 트윈 구축 가이드를 공개하면서 현장에서는 OpenUSD 도입 시점을 두고 의견이 갈렸다. 모터스포츠 팀이 실시간 차량 데이터와 시뮬레이션을 결합해 레이스 전략을 바꾸는 모습을 보며 우리도 장비 레벨부터 공정 전체로 확장하는 로드맵을 다시 짜야겠다고 느꼈다.

## 1. 현장에서 무슨 일이 있었나
AWS가 OpenUSD와 SDMA(Scene Description Modeling Architecture)를 활용해 L1 데이터 수집부터 L4 자율 제어까지 단일 파이프라인으로 구성하는 참조 아키텍처를 발표했다. 미시간 대학은 제조 현장의 디지털 트윈 과제를 풀기 위해 산학 센터를 출범시켰다. 바이오 공정 분야에서는 장비 단위 디지털 트윈이 세포 배양 공정 최적화에 적용되기 시작했다. 모터스포츠 현장은 물리 차량 데이터와 가상 시뮬레이션을 실시간으로 연결해 타이어 교체 시점과 연료 전략을 결정하는 데 디지털 트윈을 쓰고 있다. 수처리 시설은 디지털 트윈으로 유입량 변동을 예측해 약품 투입량을 조절하며 에너지 소비를 줄이고 있다. 제조 품질 관리 현장에서는 디지털 트윈이 치수 검사 데이터를 실시간으로 비교해 불량률을 낮추는 데 기여하고 있다. 업계에서는 디지털 트윈 생태계를 이끄는 10개 기업이 꼽히며 표준 경쟁이 본격화되고 있다 [출처: Ten companies shaping digital twins in manufacturing].

## 2. 왜 업계가 반응하는가
데이터가 설비별, 공정별, 시스템별로 파편화되어 있어 전체 최적화가 불가능한 상황이 지속돼 왔다. MES, SCADA, 히스토리안, 시뮬레이션 도구가 각자 포맷으로 데이터를 저장해 통합 분석에 드는 비용이 너무 컸다. 예측 정비 수요가 늘면서 단순 모니터링을 넘어 이상 징후를 사전에 탐지하고 공정 파라미터를 자동 조정하는 L3, L4 단계로 넘어가려는 압박이 커졌다. OpenUSD가 3D 에셋 교환 포맷을 넘어 시계열 데이터, 메타데이터, 시맨틱 정보까지 담는 범용 장면 기술 언어로 확장되면서 이질 시스템 간 연계 표준이 될 가능성이 열렸다. 클라우드 벤더가 관리형 서비스로 파이프라인을 제공하면서 초기 구축 장벽이 낮아진 점도 도입 검토를 앞당기는 요인이다.

## 3. 기술적으로 보면
- **L1 데이터 수집**: 센서, PLC, 히스토리안에서 시계열 데이터를 수집해 타임스탬프 정렬과 품질 검증을 수행하는 계층
- **L2 상태 시각화**: 수집된 데이터를 3D 자산 위에 오버레이해 현장 상태를 직관적으로 확인하는 대시보드 및 디지털 섀도 계층
- **L3 시뮬레이션 분석**: 물리 기반 모델이나 데이터 기반 모델로 미래 상태를 예측하고 근본 원인을 분석하는 계층
- **L4 자율 제어**: 시뮬레이션 결과를 바탕으로 설비 제어 지령을 자동 생성해 폐루프 제어를 수행하는 계층
- **OpenUSD**: 픽사가 개발한 범용 장면 기술 포맷으로 3D 지오메트리뿐 아니라 재질, 계층 구조, 시계열 샘플, 시맨틱 태그까지 확장해 산업 데이터 교환 표준으로 자리잡는 중

## 4. 실제 현장 적용 사례
수처리 플랜트는 유입수 수질 센서 데이터와 유량계를 L1로 수집해 L2에서 정수지 수위와 약품 투입 농도를 3D 맵 위에 시각화했다. L3에서는 강우 예보와 과거 유입 패턴을 학습한 모델로 6시간 후 유입량을 예측해 응집제 투입량을 사전 조절한다. 바이오 의약 공장은 바이오리액터 단위 장비에 디지털 트윈을 적용해 용존산소, pH, 교반 속도 시계열을 실시간 동기화했다. L3에서 세포 성장 동역학 모델을 돌려 배지 교체 시점과 사료 공급 프로파일을 최적화한다. 모터스포츠 팀은 차량에 장착된 수백 개 센서 스트림을 트랙 사이드 서버로 전송해 L2에서 타이어 표면 온도 분포를 3D 타이어 모델에 매핑한다. L3 랩타임 시뮬레이터가 피트인 윈도우를 계산하고 L4에서는 드라이버 알림 시스템으로 권장 기어 변속 시점을 전달한다. 제조 라인은 치수 측정기 데이터를 L1으로 받아 L2에서 공정 능력 지수 Cp, Cpk를 실시간 갱신한다. L3에서 열변형 시뮬레이션으로 툴 마모에 따른 보정값을 산출해 L4에서 CNC 오프셋을 자동 갱신한다.

## 5. 엔지니어가 봐야 할 포인트
회사에서 PoC를 진행할 때 가장 먼저 부딪히는 문제는 기존 설비 데이터가 OpenUSD 스키마에 매핑되지 않는다는 점이다. 실무에서 보면 OPC UA 컴패니언 스펙이나 AAS(자산 관리 셸) 메타데이터를 USD 스키마 속성으로 변환하는 어댑터 계층을 직접 개발해야 한다. AWS SDMA가 제공하는 샘플 파이프라인은 파이프라인 구조는 잘 잡혀 있으나 한국 플랜트 현장의 레거시 히스토리안 연동 커넥터는 별도 구현이 필수다. L3 시뮬레이션 모델을 실시간으로 돌리려면 모델 경량화와 추론 서빙 아키텍처가 별도 과제로 떠오른다. 데이터 거버넌스 관점에서 USD 레이어 스택을 어떻게 버전 관리할지, 스키마 변경 시 하위 호환성을 어떻게 보장할지 아키텍처 초기에 결정하지 않으면 나중에 마이그레이션 비용이 기하급수적으로 늘어난다.

## 6. 앞으로 볼 포인트
- OpenUSD 생태계가 산업별 도메인 스키마를 표준화해 벤더 종속성을 낮출지 여부
- L3 시뮬레이션이 물리 모델과 AI 하이브리드 형태로 현장 실시간 제어 루프 안으로 들어올 수 있을지
- 클라우드-엣지 하이브리드 아키텍처에서 데이터 일관성과 레이턴시 요구사항을 동시에 만족하는 운영 패턴 정착

## 7. 3줄 요약
- 산업별 L1-L4 레벨 정의가 명확해지면서 OpenUSD가 데이터 통합 교환 표준으로 부상 중
- 수처리, 바이오, 모터스포츠, 제조 현장에서 장비 레벨부터 공정 전체까지 적용 사례가 축적되고 있음
- 엔지니어는 레거시 데이터 매핑, 시뮬레이션 경량화, 스키마 거버넌스 세 가지를 선제적으로 설계해야 함
